# Module 12. The agent pays for its intelligence

Your agent's AI calls are paid from your Chipi credits. An agent that can pay for what it uses, per call, from its own capped budget, does not need anyone to top up an account.

## The idea

**x402** uses the HTTP status code that was reserved for this from the start, `402 Payment Required`:

```
agent ── POST /v1/ai/think + header X-PAYER: <wallet> ──▶ Chipi
      ◀─ 402 (no credits) + x402 offer:
         { scheme: "exact", network: "starknet-mainnet",
           maxAmountRequired: "15000", asset: USDC, payTo: Chipi,
           extra: { paymentMethod: "session-transfer", payableModels, maxPromptBytes,
                    payer: { address: <wallet>, accepted: true } } }
agent ── session-signed USDC transfer(payTo, 15000) ────▶ Starknet
agent ── POST /v1/ai/think + header X-PAYMENT:
         { payload: { signature: { r: txHash, s: "session" }, fromAddress, ... } } ─▶ Chipi
                                                           checks the receipt: a Transfer of
                                                           ≥ 15000 to payTo, from a wallet of
                                                           this org, a hash that pays once
      ◀─ 200 { decision, x402Payment }
```

15000 base units is $0.015. That price covers the model, the gas Chipi sponsors for your payment, and Chipi's margin, for the worst case of every payable model. Credits stay cheaper (about $0.002 a decision on haiku), because they need no payment transaction.

Why this fits the rest of the course:

- **The budget is the cap you already set.** The payment is a USDC `transfer` signed with the session key, so the USDC spending policy (module 5) meters it like any trade. The agent cannot overspend on AI either.
- **No prompt.** The session signs; you are never asked.
- **Only your org can spend your payment.** Hashes are public, so Chipi accepts a payment only from a wallet of the org that owns the `sk_`; anyone else's payment would be refused after the USDC moved. The SDK names the wallet in `X-PAYER` first, and when the offer answers `accepted: false` it refuses (`X402_PAYER_NOT_IN_ORG`) without paying. Vela's wallets are created with its own keys, so they always qualify.
- **Proof, not trust.** The seller reads the receipt, not your word (module 3), and a hash pays once. The buyer checks too: a transfer the wallet refused comes back succeeded with nothing moved (module 10), so the SDK sends a payment only after its `Transfer` shows up.

## The code

- **`sdk.ai.think(params, { payWithSession })`** in `@chipi-stack/backend` does the whole loop. It answers the 402, refuses before paying when the price is above your `maxAmount`, the model is not payable, the input is too big, or the wallet is not one of your org's (14.15.1+). It sends the `X-PAYMENT` only once the USDC moved.
- **`lib/brain.ts`, `think`:** passes `payWithSession` with the agent's wallet, session and `X402_MAX_PRICE_USDC` ($0.02).
- **`lib/config.ts`:**
  - `payAiWithX402()` turns it on with `VELA_PAY_AI_WITH_X402=true`.
  - `sessionEntrypoints()` adds `transfer` to the whitelist only then. Sessions hired before cannot pay: hire again.
- **`lib/agent.ts`:** logs what the decision really cost, credits or the x402 amount (`aiCostUsd` in `lib/brain.ts`).
