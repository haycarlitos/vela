# Module 12. The agent pays for its intelligence

> **Status: in progress.** Chipi's AI API answers `402 Payment Required` when your org has no credits; accepting payment from an agent's session is being added. This module explains the protocol now and gets its exercise when that ships.

Today your agent's AI calls are paid from your Chipi credits. An agent that can pay for what it uses, per call, from its own capped budget, does not need anyone to top up an account.

## The idea

**x402** uses the HTTP status code that was reserved for this from the start, `402 Payment Required`:

```
agent ── POST /v1/ai/think ─────────────────────────────▶ Chipi
      ◀─ 402 + header payment-required:
         { scheme: "exact", network: "starknet-mainnet",
           maxAmountRequired: "2000", asset: USDC, payTo: Chipi }
agent ── session-signed USDC transfer(payTo, 2000) ─────▶ Starknet
agent ── POST /v1/ai/think + header X-PAYMENT:
         { payload: { signature: { r: txHash, s: "session" }, fromAddress, ... } } ─▶ Chipi
                                                           checks the receipt: a Transfer of
                                                           ≥ 2000 to payTo, from a wallet of
                                                           this org, hash never used before
      ◀─ 200 { decision }
```

Why this fits the rest of the course:

- **The budget is the cap you already set.** The payment is a USDC `transfer` signed with the session key, so the USDC spending policy (module 5) meters it like any trade. The agent cannot overspend on AI either.
- **No prompt.** The session signs; you are never asked.
- **Proof, not trust.** The seller reads the receipt, not your word (module 3), and a hash pays once.

What changes in Vela: `transfer` goes back into `SESSION_ENTRYPOINTS`, `lib/brain.ts` pays when Chipi answers 402, and the AI endpoint becomes configurable so you can point your agent at any x402 seller.
